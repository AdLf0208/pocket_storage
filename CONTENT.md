# Pocket Storage — content carry (slice 1)

> **Format changed 2026-11-18.** The content no longer lives in a separate `content/`
> package: the flat SDK package carries it as `assets/` and `data/` at the port root,
> byte-identical to what this file describes. `tools/assemble_content.py` still rebuilds
> from the jar (write into `assets/` and `data/` directly, not `content/`). See
> [`notes.md`](notes.md) § *Migration to the SDK format*.

`content/` is generated by [`tools/assemble_content.py`](tools/assemble_content.py)
from the pack's jar (`ports/_shared/licence-cache/pocketstorage-1.2.5+1.21.1-b3.jar`,
SHA-256 `4c6e0522…c8303`, MIT). Rerun it to rebuild; it deletes `assets/` and
`data/` first, so nothing stale survives.

## Not carried (and why)

- **Tiers 2–4** (`psu_2..4` models are byte-identical to `psu_1`'s — one shared
  texture): the items are gaps of this slice, so their declarations, recipes and
  tabs are not carried.
- **`data/pocketstorage/recipe/tier2..4.json`**: a custom
  `pocketstorage:upgrade` recipe type the pin cannot register (gap in
  `notes.md`).
- **`assets/pocketstorage/textures/gui/*`**: the screen's textures; this slice
  carries no screen.
- **`logo.png`, `.cache/*`, `accesswidener`/AT file, `pack.mcmeta`**: packaging
  artefacts of the jar.
- **Loot tables, tags beyond the three, advancements**: the jar has none for an
  item that is not a block.

## Verified

`cargo horizon-mod build` + `check` (the pin's own `cargo-horizon-mod`) report
`no code: content only` and 11 entries, 3,207 B. In game the e2e gives the item,
holds it and reads it back (`ctl inventory` shows
`pocketstorage:psu_1` with its `pocketstorage:contents` component), and the
chat line the game prints when it is given shows the carried lang's own name
(`Pocket Storage Unit Tier: 1`), so the content half reached the item registry
with its assets in place — see `notes.md` and
`ports/_shared/evidence/pocketstorage/`.

The tier-1 recipe and the creative tab load with that same content root (a
malformed recipe refuses the mod), but **neither is exercised in game by this
slice's e2e**: the headless harness has no renderer, so `ctl click-slot` on a
crafting grid is not available, and the creative tab needs a screen. Recorded
as unverified in `notes.md`.
